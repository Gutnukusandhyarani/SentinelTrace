# SentinelTrace Interactive Dashboard

## What it is

A static, responsive dashboard built with HTML, CSS and vanilla JavaScript. It reads the files already present in this repository and does not require a backend, database, API key, npm install, or paid service.

## Dashboard URL after GitHub Pages is enabled

For the repository `Gutnukusandhyarani/SentinelTrace`, the expected URL is:

`https://gutnukusandhyarani.github.io/SentinelTrace/dashboards/`

The URL becomes active after the repository owner enables GitHub Pages and the deployment completes.

## Data sources

| Dashboard view | Repository file | How it is used |
|---|---|---|
| SIEM alert explorer | `outputs/illustrative-siem/sample_alerts.json` | 5 synthetic alert records, searchable and filterable |
| Copilot review | `outputs/copilot_demo/suggestions.json` | 30 deterministic mock-provider suggestions |
| Copilot metrics | `outputs/copilot_eval/evaluation.json` | Schema and fixture-check counts, with limitations shown |
| SSH timeline | `data/sample_auth.log` | Original 8-event OpenSSH sample parsed in the browser |

The dashboard fetches these files relative to `dashboards/index.html`. Keep the folder structure intact when merging the expansion pack into the existing repository.

## Interactive features

- Overview cards for SIEM alert counts, severity totals and SSH event counts.
- Severity mix visualization and copilot verdict distribution.
- Detection coverage cards with ATT&CK technique references.
- Search and severity/status filters for SIEM alerts.
- Search and verdict filters for copilot suggestions.
- Search and event-type filter for SSH events.
- Record inspector drawer for alert context, investigation focus, copilot evidence, unknowns and next steps.
- Export filtered SIEM alert records as CSV.
- Optional local file upload to replace the dashboard data while previewing it.
- Responsive layout for desktop and mobile widths.

## Preview locally

Run a local web server from the repository root. Do not open the HTML file directly with `file://`, because browsers normally block local `fetch()` requests from file URLs.

```powershell
py -m http.server 8000
```

Open:

`http://localhost:8000/dashboards/`

Stop the server with `Ctrl+C`.

## Publish with GitHub Pages

1. Merge the `dashboards/` folder and the expansion pack's `outputs/` files into the existing repository. Preserve the existing `data/sample_auth.log` file.
2. Commit and push the changes to the repository's default branch (currently assumed to be `main`; verify the actual branch in GitHub).
3. Open the repository on GitHub and navigate to **Settings → Pages**.
4. Under **Build and deployment**, select **Deploy from a branch**.
5. Select the default branch and the `/(root)` folder, then save.
6. Wait for the Pages deployment to complete. GitHub will display the published site URL in the Pages settings.
7. Open the dashboard at the `/dashboards/` path.

If the site is already being published from another source folder, do not change the setting without checking the existing site. Instead, copy the dashboard folder and its data dependencies into the current publishing source.

## Important limitations

- SIEM records are clearly labelled illustrative synthetic training records. They are not exported from Splunk or Microsoft Sentinel.
- Copilot records use a deterministic mock backend; the dashboard does not claim that the suggestions were generated by an LLM.
- The dashboard is a static reader and analyst-training aid. It does not connect to live SIEM, EDR, identity, or threat-intelligence services.
- No automated containment, account disablement, IP blocking or other response action is performed.
- The dashboard requires the published data files to remain available at the relative paths above. If one is absent, the related view will show partial data and a source warning.
